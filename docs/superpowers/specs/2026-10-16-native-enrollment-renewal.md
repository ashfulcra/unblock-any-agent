# Native enrollment renewal

The native pilot's sealed worker/listener credentials expire within one hour of the originating Fulcra access token. A session-independent listener cannot promise continued coverage if nothing can renew that narrow access. The existing authenticated Fulcra CLI already refreshes its own owner session; no new OAuth client registration is a prerequisite for this operator-assisted route.

Use a separate explicitly configured trusted operator process for renewal. Workers and read/route listeners keep only their own narrow sealed credentials. The operator obtains the existing CLI access token in memory, calls only the saved dashboard's owner identity/attention/prepare/enroll operations, and never copies a refresh token into a plugin, worker profile, listener, request or log. No persistent schedule is installed automatically.

The operator renews an existing enrollment anchor selected in private configuration. The owner source, not caller labels, supplies its stable agent ID, kind, environment and explicit agent set. Freeze those fields, bind the profile destination, and refuse changes. An anchor or latest grant that the owner revoked stops renewal; do not silently reenroll a revoked identity. Expired but unrevoked access may be renewed. Each new grant names the preceding grant; server authorization checks all ancestors for revocation while ignoring expired ancestor leases. This prevents an in-flight renewal from bypassing a later revocation of its predecessor. Never enroll a new identity or expand a scope through a renewal tick.

Before a write, persist the exact intent, fixed expiry and source enrollment fields. Retry uncertainty with that same body. A later definite rejection cannot erase an earlier uncertain enrollment. Rotate a private profile only after its exact grant record has been read back; preserve the previous profile while new ingestion remains pending. Replacement files are atomic, owned and mode0600, with no symlink acceptance. Concurrent operators share an exclusive private state lock. Source/CLI failure leaves known profiles and pending obligations intact and returns an explicit reconnect/recovery action.

The saved origin must match the operator's private configuration and verified owner source; redirects and environment proxies must not forward owner credentials. Only fixed API operations are available. No incoming work chooses an origin, scope, executable, destination file or credential.

Acceptance: bounded fixture tests for pending retries, expiry, revocation, frozen scope, file replacement and concurrent operators; actual short-lived enrollment renewal through the existing owner CLI; old grant fails after expiry while replacement scoped access works; the same listener identity/ledger recovers without erasing pending work. State exactly which operator/trigger was run and its lifetime. This does not prove a scheduler, indefinite refresh availability, remote ChatGPT OAuth, marketplace acceptance or arbitrary-host wake.
